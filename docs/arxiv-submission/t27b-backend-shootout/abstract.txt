t27b is the native backend of t27, a specification-first language whose source files carry their own tests. t27b lowers t27's internal intermediate representation to AArch64 machine code, runs a specification's tests in-process through a JIT, and emits relocatable objects and assembly listings. We measure it against the t27c reference pipeline (t27c gen followed by Zig 0.16 in Debug mode) and against t27c's C emitter compiled with GCC 12.2 and Clang 21.1, over the full corpus of 1,819 specifications at one pinned revision of the t27 repository. t27b passes 1,296 of the 1,311 files the reference passes (98.9%) and agrees with the reference on all 8,344 tests both ran. Its test-compile latency is 4.8 ms per specification (geometric mean over 18 specifications), 8.8x below GCC -O0 on the generated C and 640x below one Zig Debug invocation per specification; when 20 specifications share one Zig invocation the gap is 8.6x. The compiler is a 3.08 MB executable with one crate dependency and a median peak memory of 5.3 MiB. Its generated code is at the level of an unoptimising compiler: on 20 specifications selected without reference to t27b it executes 0.91x the instructions of GCC -O0 and 3.4x those of GCC -O2, runs 4.1x slower than GCC -O2 under qemu-aarch64 emulation (3.7x slower than Clang -O2 on the 9 specifications Clang did not fold at compile time), and is 1.8x larger than GCC -O2 code. The agreement result is self-consistency behind one shared front end, not an independent proof of correctness, and all run times are emulated. The measurement report and its raw JSON are committed with the repository.
