t27b is the native backend of t27, a specification-first language whose source files carry their own tests. It lowers t27's internal intermediate representation to AArch64 machine code, runs a specification's tests in-process through a JIT, and emits relocatable objects and assembly listings. We measure it against the t27c reference pipeline (t27c gen, then Zig 0.16 Debug) and against t27c's C emitter compiled with GCC 12.2 and Clang 21.1, over the 1,819-specification corpus at one pinned revision. t27b passes 1,296 of the 1,311 files the reference passes (98.9%) and agrees with the reference on all 8,344 tests both ran. Its test-compile latency, which ends with code in memory and does not link, is 4.8 ms per specification (geometric mean over 18), 8.8x below GCC -O0 compiling the generated C to an object and 640x below one Zig Debug invocation, which builds and links a test binary; when 20 specifications share one Zig invocation the gap is 8.6x. The compiler is a 3.08 MB executable with one crate dependency and a median peak compile memory of 5.3 MiB. Its generated code is at the level of an unoptimising compiler: on the 20 specifications with the most GCC -O0 instructions among the 567 that every pipeline, t27b included, passes, it executes 0.91x the instructions of GCC -O0 and 3.4x those of GCC -O2, runs 4.1x slower than GCC -O2 under qemu-aarch64 emulation (3.7x slower than Clang -O2 on the 9 specifications Clang did not fold), and is 1.8x larger than GCC -O2 code; on four crypto specifications it executes 10.1x the instructions of Zig ReleaseFast. Agreement is self-consistency behind one shared front end, not independent proof: a random-program fuzzer at a nearby commit found 7 disagreements in 1,000 programs. All run times are emulated. The report and its raw JSON are committed with the repository.
