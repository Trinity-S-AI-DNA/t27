# Gallery absence evidence: 13 panel widgets deliberately absent from the live gallery

Owner decision 2026-11-10, `T27_GALLERY_ABSENT_RECORD_V1`. Companion to
`specs/t27os/evolve.t27` (constants `GALLERY_ABSENT_*`) and
`specs/t27os/agent_parts.t27` (the panel catalog, WIDGET_COUNT = 208).

## Decision

`RECORD_13_AS_DELIBERATELY_ABSENT`. The 13 IDs below are
`DELIBERATELY_ABSENT_FROM_LIVE_GALLERY`. No widget page is built, no gallery
entry is added, the gHashTag/trinity tree is not touched, and no new
workstream starts while PR #13579 is open.

architecture-adr-soul, de-zig-migration, experience-xai, knowledge-graph,

runtime-bootstrap, universe-levels, external-bindings, yield-depin,

All 13 exist in the panel catalog (`agent_parts.t27`, indices 195..207, all
sealed, 24/24 tests pass) and none exists in the live gallery
(`https://t27.ai/widgets/gallery.t27`, 306 entries).

## Build constraint (measured, gHashTag/trinity)

The gallery generator `apps/website/scripts/widgets-from-spec.mjs` reads each
widget's own share page at `public/widgets/<id>/index.html` and fails the
build closed when the page is missing, or when the page lacks `og:title`,
`og:description` or `og:image`, or when the `og:image` file is not under
`public/`. Pages are themselves generated by `widget-pages-from-spec.mjs`
from each widget's own spec, `apps/website/specs/widgets/<id>.t27`. Verified
2026-11-10 against the working tree: none of the 13 has a spec, a page or a
card in trinity. Adding only the catalog entries would break the build.

## Required per-widget artifacts (for the future batches)

1. `apps/website/specs/widgets/<id>.t27` -- the widget's own spec with tests
2. generated `public/widgets/<id>/index.html` with OG metadata and `t27:hook`
3. generated card image under `public/`
4. the gallery entry in `apps/website/specs/widgets/gallery.t27`
5. regenerated `src/lib/queenWidgets.generated.ts` and the byte-identical
   `public/widgets/gallery.t27` copy
