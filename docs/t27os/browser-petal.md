# Browser in T27OS petal B

Petal B (Cmd+2) remains BENCH. Its RUN LOG toolbar opens the authenticated personal browser pod at `https://app.t27.ai/game/browser` (the Queen board's `browser` HUD view, which needs the user's session — not the public `t27.ai/#/queen` board) inside a native WKWebView. BACK/Escape returns to BENCH. The browser session, profile, login flow, stream and agent tools remain owned by `999-multibots-telegraf`, not by the T27OS window. The view starts only when the button is pressed; it does not start a second Chromium or connect to CDP.

The repository-local `.mcp.json` adds `queen-browser` pointing to the 999 broker's `/mcp` endpoint with `X-Agent-Key: ${VIBEE_AGENT_KEY}`. Issue the key to the same person who signed into the browser, using the 999 app's agent-key UI; put it in the Queen agent process environment outside Git. The T27OS PTY server does not mint, inject or persist this key. A Queen client that does not load this repository's MCP config or has no valid key cannot use the tools. Discover actual `browser_*` methods through `tools/list` and use `tools/call`; do not give the Queen CDP, the pod admin token or a viewer URL carrying a token. The MCP key identifies a user on the broker; the WKWebView signs in independently and must be the same user to show the same session.

The 999 broker currently has an owner-only fixed pod in production; the page cannot be advertised as multi-tenant. Its site permission guard is not a security boundary against a hostile agent: `browser_evaluate` can act on arbitrary pages. Sensitive transactions require the person's supervision and the broker's own approval flow. Do not treat T27OS's Queen panel as proof that an autonomous Queen model has executed MCP calls; that panel's current suggestions are fixed rules.

Build in this full-source checkout with `PATH=$HOME/.cargo/bin:$PATH make t27os`. The artifact is `target/t27os/T27OS.app`. Run `t27b test specs/t27os/browser_petal.t27` for the B route and hit-test contract. Actual signed-in streaming and Queen action testing requires a live broker, a personal key, the owner's login in this WKWebView and a Queen CLI loading the MCP config; no credential is stored in the checkout.
