| Message queue and interruption. `prompt` takes ordered content parts, `mode` 'queue' or 'steer', and a `requestId` that makes a retry idempotent. ## 2. Core data types for conversation state

- `SessionEvent<T>`: `{type, seq, time, data, ignorable?, surfaceOp?, sourceEventSeqs?}` -- docs/subsystems/session.md:228-296.
- `SessionEventMap`: the event vocabulary (turn/*, step/*, user/system/developer/assistant message, tool/call, tool/result, request/header, request/context, session/end-seed, plus merged compaction/*, approval/*, goal/*, todo/write, plan/mode, subagent/*) -- docs/subsystems/session.md:27-175.
- `MessageBase`: `{id: MessageId, content: ContentBlock[], source: MessageSource}`; roles system, developer, user, assistant, tool -- packages/llm/llm/src/message.ts:139-180.
- `ToolResultMessage` and `tool/result`: `{toolCallId, isError?}` inside `{turn, step, message, error?{name, code, reason?}, meta?}`; `tool/call` carries `callId, name, arguments` (raw JSON string) -- message.ts:173; session.md:109-135.
- `TurnEndReason` (`TurnEndReasonMap`): completed, aborted{cause}, blocked, error, max-tokens, interrupted, forked -- docs/subsystems/session.md:692-733.
- `SessionPromptRequest` with `PromptContentPart`, `QueueAction`, `SessionQueuedItem`: content parts, mode 'queue' or 'steer', requestId; queue edit, remove, steer -- packages/api/session-controller/src/types.ts:77,141,321,351,586.
- `SessionAddress`, `SessionEventEntry`, `SessionState`: `SessionState = {cursor, active, running, queue: SessionQueuedItem[] or null, pendingInput: ('approval','question','other')[]}` -- types.ts:402,423,597.
- `SessionFollowRequest`/`SessionFollowFrame`, `SessionObserveEventRequest`/`SessionEventFrame`, `SessionWaitRequest`/`SessionWaitValue`: reconnect and wait frames; wait reason 'idle', 'input-required', 'timeout' with `{records, truncated}` -- types.ts:487,554,615,631,646,651.
- `ApprovalRequestId`, `ApprovalOutcome`, `ApprovalPolicy`, `ApprovalRequest`: outcome allowed-once, rejected, cancelled, unavailable; policy ask or never -- docs/subsystems/approval.md:11-33,60.
- `SubagentResult`: `{output: ContentBlock[], structured?: unknown, diagnostic?: string, stopReason}`; `SubagentStopReason` completed, aborted, error, max-tokens, refusal -- docs/subsystems/subagent.md:239-264.
- Compaction events: `compaction/start {turn: number or null}`, `compaction/summary {summary, shadowedRange, shadowedSeqs, shadowedTokenCount, provider, model, ...}`, `compaction/end {turn, error?}`; `CompactionTrigger` 'pressure' or 'context-overflow' -- docs/subsystems/compaction.md:9-25,75-90.
- `GoalSnapshot`/`GoalView`/`GoalPhase`, `TodoItem`, `plan/mode`: goal id, revision, objective, phase, blockedReason, maxGoalRounds; todo `{content, status}`; plan `{active}` -- docs/subsystems/goal.md:7-90; todo.md:9-30; plan.md:9-12.

## 3. Known defects or rituals an operator meets

Only items that a doc or source comment names:

- Draft reachability. After 0.2.1-rc.2 made every "New Session" create a fresh agent, the blank session it left behind was hidden from the session tree and its unsent draft could not be reached; later versions reuse the first blank session again (docs/upgrade-guide/v0.2.1-rc.2/new-session-blank-reuse/guide.md:12-18). A reused blank whose agent is already loaded keeps the preset composition it had; restart the host after editing a preset (same guide, Migration 1).
- Unsent drafts are not saved server-side: "a composer draft stays in the browser until you submit the message" (packages/attachment/attachment/README.md:120).
- Cold-agent follow. `session.follow` no longer wakes a cold agent unless `activate: true` is passed (docs/upgrade-guide/v0.2.1-rc.3/session-follow-activation/guide.md:11,17).
- Wrong-server verification. Post-mortem 0003: a Web agent validated a replacement `dsh web` server on another port instead of the GUI the user was using, after a bare Vite 200 hid a `window.__DSH_BOOT__` white page; status resolved, guardrails added (docs/postmortem/0003-web-agent-gui-feedback-loop.md, Summary, Timeline, Root cause).
- Orphan locks and no mailbox. A `compaction/start` with no `compaction/end` blocks every compaction entry point until a newer `session/end-seed` (docs/subsystems/compaction.md:17); a child-to-parent message needs a live parent and there is no durable parent mailbox (packages/subagent/subagent/README.md:207,212).
- Double send: none found in docs. The only mitigation named is `requestId` idempotency on `prompt` (packages/api/session-controller/README.md:30-60).
- Unsent paste, reading old scrollback: none found in docs.
- Headless boot failing on credentials: none found in docs. The docs only state that provider keys live in `$DSH_HOME/.credentials.yaml` and that headless runs with `--profile headless` (docs/user/guide/providers.md:13; docs/cli-help.md:131). The failure seen on the installed rc.8 is not documented in this clone.
