LOCALIZATION UPDATE (2026-11-02):
The defect is in the t27b lowering of bitwise & | ^ between two u64 values
where at least one operand is a compile-time constant >= 2^28. Per-op
bisection confirms: AND, OR, XOR each independently produce wrong results
when both operands are large. The reference (t27c gen-zig) produces correct
results for the same expressions. The precise lowering location is in
cli/t27b/src/lower.rs, ExprBinary handler — the path that handles bitwise
ops on u64 values (not visible in the section covering logical and/or and
shift overflow detection; requires deeper investigation by the compiler
team). Not fixable within this slice's scope (frozen compiler code).
