# Board run of the PSP103 inverter, tt corner, tables in block RAM, 2026-10-20

Issue #11208 (M3d, success criterion SC-003 of the analog epic #10486), a lane of the night loop #11063. English, ASCII only.

This is the first analog board top that reads the PSP103 tables: `specs/fpga/psp103_inv_ax7203.t27` runs the 500 fF CMOS inverter of `specs/analog/mos_psp103.t27` (400 backward Euler steps of dt = 100 ps, tt current and drain-charge tables, three Newton iterations a step) on the ALINX AX7203, holds the four tables and the 400 expected samples in block RAM, and prints one UART line per step. Every number below was measured in this run.

What this document does not say: nothing about speed, power or value. Fmax is nextpnr's post-route estimate for one placement of one netlist. A PASS says the board agrees with the spec's own fixed-point run, which `mos_psp103.t27` puts within 0.020 % (rise) and 0.0041 % (fall) of ngspice's 50 % delays at tt; it does not say anything about another corner, another load or another gate waveform.

## 1. The run

- Source: the specs as committed at `8e76e1b1a` on `lane/m3d-11208` (`psp103_inv_ax7203.t27`, and `mos_psp103_data.t27` with its clocked port and `TT_RUN`). Nothing was edited between the commit and the build; the control is a scratch copy (section 2).
- Compilers: `t27c` sha256 `016fb83b7f02d045...` and `t27b` sha256 `d7ec5790dc29b3f3...`, the release binaries of the shared build directory.
- Toolchain: yosys 0.63 (git 70a11c6bf0e8dd669f56c7da3587f78b405138e2), the openXC7 fork of nextpnr-xilinx and prjxray from the shared build directory, chipdb `xc7a200tfbg484-2.bin` (md5 `59f828c441e6e6081bfee63ff994660e`), `openFPGALoader v1.1.1`.
- Board and cable: ALINX AX7203, `xc7a200tfbg484-2`. `t27c boards` named the cable: `--busdev-num 1:4   idcode 0x3636093   family artix a7 200t` (Digilent HS2, FT232H). UART: the CP2102N bridge of the board, 115200 baud 8N1, pin N15, read by one reader from the terminal tab of the desktop app, started before the load; the port was free before and after.
- Programming: SRAM only (`openFPGALoader` without `-f` or `-m`; the output shows `Load SRAM` and `done 1`). No flash memory and no eFUSE was written.
- Disk: free space on `/` was 5.3 to 6.5 GiB during the run (the lane brief's floor is 5 GiB); each 22 MB frames file was deleted once its bitstream existed.

## 2. How it was built

`$O` is the shared openXC7 build directory, `$B` a scratch output directory.

```
t27b verilog specs/fpga/psp103_inv_ax7203.t27 > $B/top.v          # 1215 lines, module FpgaPsp103Inv
t27c gen-verilog specs/analog/mos_psp103_data.t27 > $B/data.v     # 39959 lines, module AnalogMosPsp103Data
yosys -l $B/x.log $B/x.ys
  # x.ys:
  read_verilog -sv $B/top.v $B/data.v
  synth_xilinx -family xc7 -top FpgaPsp103Inv -flatten -abc9 -nodsp -nosrl -run :coarse
  techmap -map +/cmp2lut.v -map +/cmp2lcu.v -D LUT_WIDTH=6
  alumacc
  opt
  memory -nomap
  opt_clean
  setattr -set ram_style "block" t:$mem_v2
  synth_xilinx -family xc7 -top FpgaPsp103Inv -flatten -abc9 -nodsp -nosrl -run map_memory:
  stat
  write_json $B/x.json
$O/np-main/build/nextpnr-xilinx --chipdb $O/xc7a200tfbg484-2.bin --json $B/x.json --fasm $B/x.fasm --freq 100 [--seed 2] --log $B/x.pnr.log
PYTHONPATH=$O/prjxray $O/venv/bin/python3 $O/prjxray/utils/fasm2frames.py --db-root $O/prjxray-db/artix7 --part xc7a200tfbg484-2 $B/x.fasm $B/x.frames
$O/px-main/build/tools/xc7frames2bit --part_file $O/prjxray-db/artix7/xc7a200tfbg484-2/part.yaml --part_name xc7a200tfbg484-2 --frm_file $B/x.frames --output_file $B/x.bit
openFPGALoader -c digilent_hs2 --busdev-num 1:4 $B/x.bit          # SRAM only
```

The pins are attributes in the spec, so there is no constraint file and no hand-written Verilog: the board top is `t27b verilog` output, the RAM is `t27c gen-verilog` output. The one line that is not in the spec is `setattr -set ram_style "block"`, a yosys directive in the build script (see section 6).

The negative control is the same `top.v` and a `data.v` generated from a scratch copy of `mos_psp103_data.t27` whose `on_clock` reads `SS_N`, `SS_P`, `SS_QD_N`, `SS_QD_P` instead of the four `TT_` tables (the copy lived in `specs/analog/` for one command, because a `use` does not resolve elsewhere, and was deleted). The two generated `data.v` files differ in exactly four lines, the four table reads. The expected samples (`TT_RUN`) are the tt ones in both.

## 4. The captures

Each capture is 7 seconds, one reader, started before the load. A line is well-formed when it matches `T27 PSP N=<3 hex> Y=<7 hex> E=<7 hex> S=<16 hex> L=<4 hex> (PASS|FAIL)` exactly; only well-formed lines are counted. Before the new configuration took over, the previous design on the board was still printing: in the tt capture 17 lines of the SAR top and a fragment, in the control capture ten whole lines of the tt top (L = 0xD4F6 and up) and three fragments. The last line of each capture is cut where the reader is killed. ## 5. Tests

`t27c test-report specs/fpga/psp103_inv_ax7203.t27`: 15 tests, 15 pass, 0 fail, 0 vacuous (runtime asserts per test from 11 to 14482). `t27c test-report specs/analog/mos_psp103_data.t27`: 11 tests, 11 pass, 0 fail, 0 vacuous. `t27b test specs/fpga/psp103_inv_ax7203.t27 --check` and `t27b test specs/analog/mos_psp103_data.t27 --check` exit 0; for the board top t27b prints `runtime asserts unknown`, because its interpreter's fuel (20 million steps a file, `specs/tri/t27b/check_budget.t27`) runs out in the whole-run tests (a 400-step run is about 760000 clocks, and the UART test and the control run it again): the JIT ran all 15 tests and they pass; the interpreter agrees on the part it had fuel for.

## 6. What differed from the plan, and traps

1. **`t27c gen-verilog` writes nothing for an array that came in by `use`.** The reference is left undeclared (the same defect #8769 records for functions), so the tables could not be read from the board spec. The memory is therefore generated from the module that owns the arrays: `mos_psp103_data.t27` got a clocked port next to them (`on_clock(addr, idx)`, five output registers) and the board top instantiates it as an extern, like the PLL. A minimal repro for #5980: a spec with `use analog::mos_psp103_data::{TT_N};` and `on_clock` reading `TT_N[addr]` generates Verilog with `TT_N` undeclared.
2. **yosys maps a 625-word ROM to flip-flops and LUTs** (about 1270 LUT, 909 of them LUT6, and 79 FDRE for the four tables in a probe) unless the memory carries `ram_style = "block"`; with it the same module is 4 RAMB36E1 and no LUT. `gen-verilog` cannot write the attribute, so the build script sets it with `setattr` on the `$mem_v2` cells. Worth a rule in `gen-verilog` (an attribute on a const array that the spec marks) or in `t27c silicon`.
3. **A `const rst_n` in a `gen-verilog` module makes yosys refuse the process** (`negedge` of a constant: "Multiple edge sensitive events found"). The data module leaves `rst_n` and `en` as ports and the top ties them to 1, which `flatten` and `opt` fold into plain flip-flops, so the memory's read register merges into the block RAM.
4. **Names of module vars must not collide with locals of imported functions** (`acc`, `y0`, `lo`, `hi`, `cx`, `fx`: `blend`, `id_of` and the rest declare them): t27b refuses a local that shadows a module var. The datapath registers are `r_`-prefixed.
5. **Read before write.** `on_clock` assigns with non-blocking semantics in hardware; the tests run it sequentially, so a var read after its own assignment in the same call (a counter incremented, then compared) passes in hardware and fails in the test or the reverse. Two such places were found by the divider test and reordered.
6. **The control missed timing once**: with the default seed the ss build reached 96.57 MHz after routing (FAIL at 100); seed 2 gave 107.33 MHz. The tt top closed at the default seed.
7. The reader attached before the load saw the previous design's lines; the judge starts at the first `L=0000`, `N=000` line.

## 7. Not claimed

No speed claim (a step is about 1700 to 1960 clocks, 19 us at 100 MHz; the line of a step is 5.7 ms of UART; nothing here is compared with ngspice's wall time). No power. tt only: the other four corners are other tables and no other bitstream was built. One gate waveform (two levels, an ideal step), one load (500 fF with dt = 100 ps). The expected samples are the spec's own output stored in the RAM, so a PASS is agreement with the spec, not with ngspice; the spec's distance to ngspice is the one `mos_psp103.t27` measures.
