# Specs whose Verilog carries a width that cannot be real.
# See tools/check_verilog_widths.py for what this is and why the
# compiler-side fix is a maintainer decision. Tracked as issue #2566.
#
# Removing a line is a repair. Adding one is a regression.
#
# The one line left is NOT an underflow, and the arithmetic below is correct:
#
#   Str  { data: [4096]u8; len: u32 }   = 4096*8 + 32          = 32,800 bits
#   Map  { keys: [64]Str; values: [64]Str; count: u32 }
#                                       = 2*64*32800 + 32   = 4,198,432 bits
#
# 513 KiB in one packed register. The backend computed it faithfully; the
# spec asked for something that has no hardware form. Whether a type this
# large should be lowerable at all is a design decision, not a bug fix, and
# it belongs with the same question about zero-width types in #2566.
#
# Recorded here so the next reader does not spend an evening looking for a
# subtraction that is not there. Two of the three mechanisms this ledger
# once held WERE underflows (u32 and usize) and are fixed.
specs/compiler/stdlib.t27
#
# specs/base/ternary_memory.t27 -- the SECOND line, and it is not new damage.
# The spec could not parse at all until the source a counter overwrote was
# restored, so it had never reached this gate. Same class as the line above,
# and the arithmetic is likewise exact:
#
#   TritCell    { value: i32; state: u8; last_access: u64; access_count: u32 }
#                                        = 32 + 8 + 64 + 32       =       136
#   TernaryWord { trits: [27]TritCell; state: u8; checksum: u32 }
#                                        = 27*136 + 8 + 32        =     3,712
#   TernaryMemoryBank { words: [1024]TernaryWord; allocated: usize;
#                       total_accesses: u64 }
#                                        = 1024*3712 + 32 + 64    = 3,801,184
#
# `[3801183:0]`, derived independently and matching the emitter bit for bit.
# 464 KiB in one packed register: the backend computed it faithfully and the
# spec asked for something with no hardware form. TRIT_CAPACITY is 27, which
# is 3^3 -- the size is deliberate, not a slip.
specs/base/ternary_memory.t27
#
# specs/tri/t27b/conformance/big_frame.t27 -- the THIRD line, added with the
# spec in #8764 (see #8902). Same class again: no subtraction, a size the spec
# asks for on purpose. It is t27b's frame-size conformance spec (#8758), whose
# whole point is local arrays of more than 1 MiB on the stack:
#
#   far_ends   low, high : [600000]u8   = 600000*8   = 4,800,000 bits
#   deep_big   block     : [1200000]u8  = 1200000*8  = 9,600,000 bits
#
# `[4799999:0]` and `[9599999:0]`, as the emitter prints them. Its other
# locals stay under 2^20 bits (Tape is 65536*8 + 64 = 524,352; mid_frames'
# block is 80,000), and its test body's [1100000]u8 is not emitted at all.
# Smaller arrays would remove what the spec tests; it has no hardware form.
specs/tri/t27b/conformance/big_frame.t27
#
# specs/claw/suggest_feed.t27 -- not a bus: the suggestion driver keeps a
# file's text and its formatted twin in fixed byte arrays (fc [131072]u8,
# fo [524289]u8, arena [262144]u8), which the emitter prints as [2097151:0]
# and [4194311:0]. Host-side text plumbing with no hardware form (#10365).
specs/claw/suggest_feed.t27
#
# specs/t27f/token_floor.t27 -- not a bus: the frame renderer's working
# memory. The widest local of the frame function, and its width is exact:
#
#   rsp  : [524288]u16   = 524288*16   =  8,388,608 bits  -> [8388607:0]
#          the per-frame row index (#10391): each raster row visits only the
#          splats that touch it; INDEX_CAP entries, sized by index_bound()
#
# The splat arrays ([45312]f64, MAX_SPLATS = every dot, its mirror image and
# 256 more) are 2,899,968 bits each. The cached empty scene bgq of #10407 is
# gone: with a moving camera and a per-frame dither no two frames share an
# empty scene. The index cannot shrink without removing what the spec does:
# it is what makes a frame cost its splats rather than its pixels. The spec
# renders 1080x1920 and 1920x1080 video on a host; it has no hardware form.
# Same class as big_frame.t27 and suggest_feed.t27.
specs/t27f/token_floor.t27
